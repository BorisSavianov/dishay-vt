# „Кой замърсява?“ (sources estimate): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** split each VT forecast day into PM2.5 shares (отопление / трафик / пренос / друго, labelled as an estimate), and add a 20%-heating-switch what-if line. Both are shown on the web and in the bot.

**Architecture:**
- A new `ml/aq_sources.py` has:
  - a CLI that builds hour × daytype increment profiles from pre-holdout history, computes last winter's what-if, and writes `ml/models/aq_sources.json` (committed);
  - pure functions that split forecast hours.
- `run_once` adds `daily[].sources` to the featured VT stations, plus `model.sources_what_if`.
- The web and the bot read those fields.

**Tech stack:** Python (numpy, pandas), pytest through `uv run --group ml`; Next.js and vitest for the web and the bot.

**Spec:** `docs/superpowers/specs/2026-11-20-sources-design.md`

**Owners:** Tasks 1–4 Teodor (`teodor/aq-ml`), Task 5 Velko, Task 6 Boris. Tasks 5 and 6 can start once Task 3 is pushed, since that task carries the contract.

## Global constraints

**Geometry and data**
- VT = sensors and stations within 10 km of (43.0786, 25.6211). Regional = 15–80 km. Distance uses `np.hypot((lat − 43.0786)·111.2, (lon − 25.6211)·81.3)`, as `aq_episode.py` does.
- Profiles use only hours before `HOLDOUT[0]` (2025-10-01). The last-winter what-if uses the holdout `HOLDOUT[0]..HOLDOUT[1]`.
- Warm hours are ERA5 `temperature_2m` > 10 °C at the VT cell.
- Daytype: weekend = Sat or Sun or a BG holiday (`ml.aq_features._bg_holidays`), in local time.
- A baseline cell needs at least 30 samples; otherwise it uses the hour's median across both daytypes.

**Split arithmetic**
- `regional = min(vt, reg)`, where a NaN `reg` counts as 0
- `inc = vt − regional`
- `base = min(inc, baseline[daytype][hour])`
- `traffic = min(base, traffic[hour])` on weekdays, 0 at weekends
- `other = base − traffic`
- `heating = inc − base`
- No part is ever negative, and the four always add up to `vt`.
- Day shares are rounded to 2 decimals and sum to exactly 1.00. The rounding leftover goes to the largest part.

**What-if**
- The share is fixed at 0.2. "Evening" means 18:00–23:59 local.
- Bad day = EAQI ≥ 3 from the daily mean PM2.5 and PM10 (`level_of`), with at least 18 observed hours. After the switch, each hour's PM10 is scaled by that hour's PM2.5 ratio, after/before.

**Wording**
- Every place shows „оценка“. Text order: отопление · трафик · пренос; „друго“ appears only in the bar.

## Review focus

1. **No regional stations are forecast, or their forecasts are NaN.** Regional = 0, nothing raises, and shares still sum to 1. Covered by a test in Task 4.
2. **The VT forecast is below the regional percentile** (windy, clean day). All parts are ≥ 0 and regional = vt. Covered by a test in Task 2.
3. **Day 3 has fewer than 24 forecast hours.** Shares come from the available hours. Covered by a test in Task 4.
4. **A weekend or BG holiday** gives no traffic share. Covered by a test in Task 2.
5. **A clean day** (daily `pm25_mean` < 5): the web hides the bar but the data still carries shares. Covered by a test in Task 5.
